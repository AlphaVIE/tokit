# Executable baseline protocol

The executable fixtures are [sum-positive](sum-positive/contract.json), [checked-division](checked-division/contract.json), [generic-pair](generic-pair/contract.json), and [line-count](line-count/contract.json). Each has eight implementations covering Tokit, Rust, Go, C, C++, Python, TypeScript, and Java. Their `scripts/verify_*.py` programs compile or run each available implementation and check every case against its contract. `--require-all` makes missing toolchains a failure; the CI baseline job uses it. A local run reports tested and skipped languages explicitly.

For Tokit, the harness appends a generated `main` to the marked source for each input, because this early subset has no command-line argument API. The line-count harness also grants read access to its temporary input directory. Other baselines receive inputs as command-line arguments. The `BENCH_START`/`BENCH_END` region isolates the core definitions for syntax-token comparison; the wrappers are execution adapters and must be included in future full-program workload comparisons.

The numeric contracts avoid arithmetic overflow. Python and TypeScript have different general numeric semantics, while C and C++ require care around signed overflow; passing these bounded cases establishes behavior only for the specified inputs. It does not prove full `i32` semantic equivalence. The measured [sum-positive](sum-positive/RESULTS.md), [checked-division](checked-division/RESULTS.md), [generic-pair](generic-pair/RESULTS.md), and [line-count](line-count/RESULTS.md) core counts are small source-only observations, not speed or overall token-advantage claims. The remaining task-square research fixture still needs an executable contract and baselines.
