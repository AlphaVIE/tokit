# Executable baseline protocol

The executable fixtures are [sum-positive](sum-positive/contract.json) and [checked-division](checked-division/contract.json). Each has eight implementations covering Tokit, Rust, Go, C, C++, Python, TypeScript, and Java. `scripts/verify_sum_positive.py` and `scripts/verify_checked_division.py` compile or run each available implementation and check every case against its contract. `--require-all` makes missing toolchains a failure; the CI baseline job uses it. A local run reports tested and skipped languages explicitly.

For Tokit, the harness appends a generated `main` to the marked source for each input, because this early subset has no command-line argument or standard I/O API. Other baselines parse command-line integers. The `BENCH_START`/`BENCH_END` region isolates the core definitions for syntax-token comparison; the wrappers are execution adapters and must be included in future full-program workload comparisons.

Both contracts avoid arithmetic overflow. Python and TypeScript have different general numeric semantics, while C and C++ require care around signed overflow; passing these bounded cases establishes behavior only for the specified inputs. It does not prove full `i32` semantic equivalence. The measured [sum-positive](sum-positive/RESULTS.md) and [checked-division](checked-division/RESULTS.md) core counts are small source-only observations, not speed or overall token-advantage claims. The remaining research fixtures still need executable contracts and baselines.
